## 1. Overview

A lightweight, real-time collaborative grocery list app for a household of 3–4 people. Designed for daily use on iPhone/iPad and web browsers. Inspired by the simplicity of iOS Reminders, but purpose-built for grocery shopping — organized by store and aisle, with smart item suggestions, a reusable staples list, barcode scanning, and voice input.

---

## 2. Goals & Non-Goals

### Goals
- Enable any household member to add, check off, and manage grocery items in real time
- Organize shopping by up to 3 stores, each subdivided by aisle/category
- Provide a persistent Staples List to quickly seed active shopping lists
- Surface smart item suggestions based on purchase history
- Support barcode scanning and voice input for fast item entry
- Keep the UI minimal — no excess features, no clutter

### Non-Goals
- Recipe management or meal planning
- Price comparison or external retailer integration
- Social/sharing features beyond the household
- Budget tracking or expense reports
- Push notification reminders on a schedule

---

## 3. Users

| Role | Description |
|---|---|
| Household Member | Any of the 3–4 people who add, edit, or check off items |
| List Owner | The person who sets up stores, aisles, and the staples list (initially one person, can be any member) |

All users have equivalent permissions within the household. No admin/guest tiers in v1.

## 4. Core Features

### 4.1 Store Lists
- Up to **3 named stores** (e.g., Trader Joe's, Costco, Whole Foods)
- Each store has a configurable set of **aisles/sections** — up to **10 aisles per store** (e.g., Produce, Dairy, Frozen, Meats, Snacks, Bakery)
- Aisles are user-named and **drag-to-reorder** within a store; order is persisted and shared across all household members
- Items belong to one store and one aisle
- Stores appear as top-level tabs; aisles appear as collapsible sections within each store tab

### 4.2 Item Management
- Add items by typing, voice, or barcode scan
- Each item has:
  - **Name** (required)
  - **Quantity + Unit** (e.g., 2 lbs, 1 bunch, 3 cans) — optional
  - **Store** (required)
  - **Aisle** (required)
  - **Notes** (optional, e.g., "low-sodium")
  - **Source** (`manual` | `staples` | `suggestion`)
- Drag-to-reorder items within an aisle
- Inline edit by tapping any field

### 4.3 Checking Off Items
- Tap to check off → item gets a **strikethrough** and moves to a faded "Checked" subsection at the bottom of its aisle
- Checked items persist with strikethrough until the user taps **"End Trip"** within that store's tab
- Each store tab has its own **"End Trip"** button, scoped to that store only — checking off at Costco does not affect the Trader Joe's list
- Tapping "End Trip" shows a confirmation prompt ("Clear all checked items from [Store]?") before removing them
- Unchecking restores the item to its normal position

### 4.4 Staples List
- A single persistent list of household staples (separate from active shopping lists)
- Staples have: Name, default Store, default Aisle, default Quantity/Unit
- **Copy to Active List**: User selects one or more staples and taps "Add to [Store]" — selected items are copied (not moved) into the active shopping list
- Staples can be added/edited/deleted independently of the active lists
- Staples list is shared across all household members

### 4.5 Smart Suggestions
- **Inline (while typing):** When a user starts typing in the "add item" field, suggestions appear based on:
  1. Exact/prefix match from item history
  2. Frequency (items bought often surface higher)
  3. Recency (items bought recently surface higher)
  - Suggestions auto-fill Store and Aisle based on where the item was last added

- **Dedicated "Suggestions" Tab:** A fifth tab in the main navigation surfaces proactive recommendations in two categories:
  1. **"Might be running low"** — items from purchase history not bought in the last N days (default: 14 days), ranked by historical purchase frequency
  2. **"AI picks for you"** — pattern-based suggestions generated by analyzing the household's purchase history (e.g., items typically bought together, seasonal patterns, items always bought at the same cadence). Uses a lightweight on-demand AI inference call.
  - Each suggestion card shows: item name, store, aisle, and last purchased date
  - Users can tap **"Add to list"** directly from the suggestion, or **dismiss** to hide it temporarily
  - Dismissed suggestions resurface after 7 days unless purchased

### 4.6 Barcode Scanning
- Camera-based barcode scan (UPC/EAN) on iOS and web (where camera permission is granted)
- Product name looked up via **Open Food Facts** (free, open, no API key required)
- Pre-fills item name; user selects store, aisle, and quantity before confirming
- If barcode not found in Open Food Facts, falls back to manual name entry
- Scanned barcodes stored on `ItemHistory` for future offline recognition of previously scanned items

### 4.7 Voice Input
- Tap a microphone icon to dictate one or more items (e.g., "Add two gallons of milk to Costco, dairy")
- Uses device speech recognition (iOS: SFSpeechRecognizer; Web: Web Speech API)
- Parsed result is shown for confirmation before adding — user can edit fields before saving
- Supports natural phrasing: "milk", "2% milk", "3 cans of black beans"

### 4.8 Real-Time Sync
- All changes (add, check, uncheck, delete, end trip) sync instantly across all household members' devices
- Conflict resolution: last-write-wins per item field
- Offline support: changes made offline are queued and synced on reconnect
- Visual indicator shows when a member is actively shopping (e.g., "Sarah is shopping at Whole Foods")

## 8. Sync & Offline Behavior

- **Real-time:** Supabase Realtime subscriptions push changes to all connected clients
- **Offline queue:** Unsynced mutations stored in local state (e.g., MMKV on RN, IndexedDB on web); replayed on reconnect
- **Conflict strategy:** Last-write-wins per field, with `updated_at` as the tiebreaker
- **Presence:** Supabase Presence channel to show which member is actively shopping at which store

---

## 9. Permissions & Security

- Row-Level Security (RLS) enforced at the database level: all queries scoped to `household_id`
- **Invite flow:** An existing household member generates a unique invite link (e.g., `app.example.com/join?token=abc123`) from within the app. The link is copied to clipboard for sharing via any channel (text, email, etc.) — no in-app send functionality required in v1. The token is single-use, expires after 48 hours, and is stored in an `HouseholdInvite` table. A new user clicks the link, creates an account (or signs in), and is automatically added to the household.
- No data is accessible outside the household's RLS scope

### `HouseholdInvite` (new table)
```
id            UUID       PK
household_id  UUID       FK → Household
token         string     unique, indexed
created_by    UUID       FK → User
created_at    timestamp
expires_at    timestamp  (created_at + 48 hours)
used_at       timestamp?
used_by       UUID?      FK → User
```

## 12. AI Suggestions — Rules Engine Spec

The Suggestions tab is powered entirely by a server-side rules engine. No external AI service is called in v1. All logic runs as a **Supabase Edge Function** (`suggestions/generate`) invoked on-demand when the user opens the Suggestions tab, with results cached per household for up to 6 hours.

---

### 12.1 Architecture Overview

```
Client (opens Suggestions tab)
  │
  ▼
GET /functions/v1/suggestions/generate?household_id=...
  │
  ▼
Edge Function
  ├── Queries ItemHistory (last 180 days)
  ├── Queries GroceryItem (currently active, unchecked)
  ├── Runs Rule Set (see §12.3)
  ├── Scores + deduplicates candidates
  ├── Filters out already-on-list items
  └── Returns ranked suggestion list (max 20)
  │
  ▼
Client renders Suggestions tab, grouped by rule category
```

Results are written to a `SuggestionCache` table and served from cache on subsequent opens within the 6-hour window. A manual "Refresh" pull-to-refresh invalidates the cache.

### 12.3 Rule Set

Rules are evaluated in order. Each rule produces a set of **candidate items** with a base score. Candidates from multiple rules are merged, with scores summed when the same item appears in more than one rule's output.

---

#### Rule 1 — Overdue Staple
**"This item is on your staples list and hasn't been bought recently."**

```
Trigger:  item EXISTS in StapleItem for this household
          AND item NOT in active GroceryItem (unchecked)
          AND (no matching ItemHistory row in last N days
               OR no ItemHistory row ever)

Score:    Base 80
          + 10 if never purchased (truly new staple, user just added it)
          + 10 if days_since_last_purchase > 2× avg_purchase_interval
          − 20 if days_since_last_purchase < avg_purchase_interval × 0.75

Category: "Might be running low"
```

`avg_purchase_interval` is computed per item from `ItemHistory`:
```sql
SELECT
  name,
  AVG(
    EXTRACT(EPOCH FROM (purchased_at - LAG(purchased_at)
      OVER (PARTITION BY name ORDER BY purchased_at))) / 86400
  ) AS avg_interval_days
FROM item_history
WHERE household_id = $1
GROUP BY name
```

---

#### Rule 2 — Frequency + Recency Decay
**"You buy this often and it's been a while."**

```
Trigger:  item appears >= 3 times in ItemHistory (last 180 days)
          AND item NOT in active GroceryItem (unchecked)
          AND days_since_last_purchase > 7

Score:    Base 60
          + frequency_score     (purchase_count / 180 × 100, capped at 30)
          + recency_decay_score (see formula below)

Category: "Might be running low"
```

Recency decay — score increases the longer since last purchase, up to a cap:
```
recency_decay_score = MIN(30, (days_since_last_purchase − 7) × 1.5)
```

So an item last bought 7 days ago scores +0, last bought 21 days ago scores +21, last bought 30+ days ago scores +30.

---

#### Rule 3 — Co-purchase Association
**"Items that tend to be bought in the same trip as something on your list."**

```
Trigger:  household has >= 10 completed trips in ItemHistory
          AND active GroceryItem list is non-empty

Method:
  1. For each active (unchecked) item on the current list,
     find all ItemHistory records bought within the same
     "trip window" (same household, same store, purchased_at
     within 2 hours of each other).
  2. Collect all co-purchased item names across those trips.
  3. Score each co-purchase candidate by how often it
     appeared alongside the active item.
  4. Exclude any item already on the active list.

Score:    Base 50
          + (co_occurrence_count / total_trips_with_anchor) × 40

Category: "AI picks for you"
```

Example: if "oat milk" is on the Trader Joe's list, and in 8 of 12 past trips where oat milk was bought, "granola" was also bought — granola gets score 50 + (8/12 × 40) = 77.

---

#### Rule 4 — Periodic Pattern
**"You tend to buy this on a predictable cadence."**

```
Trigger:  item appears >= 4 times in ItemHistory
          AND std_dev of purchase intervals < 5 days
             (i.e., purchased on a consistent schedule)
          AND days_since_last_purchase >= (avg_interval − 3 days)
          AND item NOT in active GroceryItem

Score:    Base 70
          + 20 if days_since_last_purchase >= avg_interval
          + 10 if days_since_last_purchase >= avg_interval + 3

Category: "Might be running low"
```

This rule catches things like "they buy sparkling water every 10 days like clockwork."

---

#### Rule 5 — Never-tried Staple Variant
**"You have a staple but have never bought a common variation of it."**

```
Trigger:  item EXISTS in StapleItem
          AND a variant of the name EXISTS in ItemHistory
             for OTHER households (global anonymized data, future)

Status:   DEFERRED — requires cross-household data.
          Not implemented in v1. Placeholder for v2.
```

---

### 12.4 Scoring, Ranking & Output

After all rules run, candidates are:

1. **Merged** — if the same item name (normalized: lowercased, trimmed) appears from multiple rules, scores are summed and categories are assigned to the highest-scoring rule's category.
2. **Filtered:**
   - Remove items currently on any active shopping list (unchecked)
   - Remove items in `SuggestionDismissal` where `resurface_at > NOW()`
   - Remove items with a final score below **40** (noise threshold)
3. **Ranked** by final score descending
4. **Capped** at 20 total suggestions (10 per category max)

#### Output shape (stored in `SuggestionCache.suggestions` jsonb):
```json
[
  {
    "item_name": "oat milk",
    "store_id": "uuid",
    "store_name": "Costco",
    "aisle_id": "uuid",
    "aisle_name": "Dairy",
    "score": 112,
    "category": "might_be_running_low",
    "rules_matched": ["overdue_staple", "frequency_recency"],
    "days_since_last_purchase": 18,
    "last_purchased_at": "2026-05-27T10:00:00Z"
  }
]
```

### 12.5 Execution & Performance

| Concern | Approach |
|---|---|
| Cold start | Edge Function stays warm; query limited to 180-day window with indexed `household_id` + `purchased_at` |
| Query cost | All rules run in 2–3 SQL queries with CTEs; no N+1 patterns |
| Caching | Results cached 6 hours in `SuggestionCache`; stale cache served if Edge Function errors |
| Minimum data | Rules 1 and 2 work from day 1 (staples list). Rule 3 requires 10+ trips. Rule 4 requires 4+ purchases of an item. Suggestions tab shows graceful empty state until enough history exists. |
| Privacy | All queries are RLS-scoped; no cross-household data access in v1 |

---

### 12.6 Future Upgrade Path (v2)

When/if the household wants smarter suggestions beyond the rules engine, the architecture supports a clean upgrade:

- Add a `suggestions_source` field to `HouseholdSettings` (`rules` | `llm`)
- Gate an LLM call (e.g., Claude via Anthropic API) behind an opt-in toggle in Settings
- Pass the last 90 days of `ItemHistory` as structured JSON in the prompt
- Cap to 1 call per household per day; cost at typical usage: < $0.01/day
- Rules engine remains the fallback if LLM call fails or toggle is off
